# Trivia host-flow refactor plan

Status: scoped review and implementation plan, 2026-10-30. The geography simplification and small music host-control fix are implemented in the working branch. The broader shared-panel refactor below remains planned.

## Accepted behavior

Every selected trivia cell has three host areas in a stable order: **题目**, **抢答与公布答案**, **记分与修正**. The middle and last areas use the same controls, labels, scoring selector, award history, and correction path for text, music, geography, and adventure. The 题目 area changes by clue kind: plain question; audio player; Street View; or adventure rules, timer, challenge progress and AI photo score. The same saved board, buzzer, award ledger and reveal state remain authoritative. Do not change cell values, existing event answers, team balances, or later party stages.

The host judges every answer. Geography shows a curated panorama, the team answers aloud, and the host judges the country or city name. It has no typed input, Geocoding API call, distance threshold or automatic score. A failed first try may be followed by one host-opened opposing-team attempt; after two tries the cell closes with no point. Adventure keeps its rule page, timers, no-repeat question pools, Yes/No visibility control and photo score threshold. Only the team selected for a first adventure attempt plays; a second team can try only when the host chooses 抢答 after first-attempt failure.

## Additional logic flaws and risks found

1. `MusicClip` calculates end and remaining time with the absolute clip end while its saved position starts at zero. A nonzero `clipStartSeconds` can run too long or resume incorrectly. Use `duration = end - start` consistently in server start/stop/projection and client countdown. Add a deterministic nonzero-start test.
2. Music playback uses a direct `command` call, bypassing the host action's pending guard and success feedback. Route start/stop through the same `host()` wrapper and disable repeat clicks until acknowledgment. TV still needs its own one-time sound-enable gesture because browsers can block autoplay; make this state explicit.
3. The ordinary host panel counts eligible teams but does not expose the two-attempt limit. With more than two teams, the UI can offer “开启抢答” after two failures even though the server rejects it. Project attempts used from the server, disable the button at two, and show “本题两次机会已用完”. Keep server rejection authoritative.
4. Adventure duplicates `arm`, `close-buzzer`, `award`, and `finish-cell` controls in a kind-specific panel. That invites mismatched disabled states and hides ordinary undo/correction affordances. Use one action bar and one scoring section, with computed capabilities from authoritative server state.
5. Ordinary `award` permits the host to select any assigned team, including before a buzz. This supports manual judgement, but the default first team can produce an accidental award. Show an explicit “选择获奖队伍” placeholder until a winner exists or the host intentionally chooses one. Keep manual override possible, and include the chosen team in a confirmation label before saving.
6. The event bank is frozen per room. Updating its geography wording does not alter an already-open room; use a new party or a pristine bank switch for rehearsal. Do not mutate saved board snapshots silently.
7. The interactive Google panorama includes a built-in “Open this area in Google Maps” link whose URL exposes the scene coordinates. A player at the display computer can use it to reveal the answer. Do not remove Google attribution or links without checking provider terms. For the current host-judged game, keep the display supervised and agree on a no-external-navigation rule; if strict anti-cheat is required, choose a licensed viewer whose navigation controls can be limited.
8. Existing schema-v17 local databases may contain old geocoder results. The current app reads those databases but ignores that table. Do not derive scores or host decisions from it; a future maintenance migration may remove it only after checking backups and deployed schema history.

## Implementation sequence for the shared host panel

1. **Write the transition table before editing UI.** For each selected cell record `kind`, board selection, reveal state, buzzer state, accepted winner, attempts used (0–2), active award, correction target, and adventure phase. Specify which actions are enabled in each state. Common rules: reveal closes an armed buzzer and blocks new buzzes; wrong answer clears winner/excludes that team without a deduction; award credits the frozen cell value once to each teammate; finish marks the cell used; undo creates a reversal and re-award uses the same cell value. For adventure, `waiting/rules/active/result/steal/won/closed` must continue to enforce timer and target constraints before common scoring can save an award.
2. **Expose server capabilities rather than repeating predicates in JSX.** Add a host-only `controls` projection from `triviaProjection`: `canArm`, `canCloseBuzzer`, `canMarkIncorrect`, `canReveal`, `canAward`, `awardableTeamIds`, `canFinish`, `canCancel`, `attemptsUsed`, and a short disabled reason where useful. Compute it from `trivia_state`, exclusions, board reveal, active award, and `AdventureState`. Keep all server-side `requireRule` checks; capabilities guide UI only and cannot authorize commands. Retain the exact stale cell/window/attempt guards.
3. **Extract three host sections.** In `Trivia.tsx`, render `TriviaQuestionPanel` for all kinds, `TriviaBuzzerAndReveal` once, and `TriviaScoreAndCorrections` once. `TriviaQuestionPanel` delegates to `TextQuestion`, `MusicClip`, `TriviaLocation`, or an `AdventureChallengeControls` component. Move music start/stop and all adventure-specific timer/progress/show-hide/replace actions into that question panel. Keep answer display private on host and reveal answer only on TV after the shared reveal action.
4. **Connect adventure to common actions carefully.** Preserve `adventure-choose-team`, start, correct/skip, success/fail/replace/score and steal transitions as challenge-state actions. Let shared award call the existing `award` transaction after verifying `AdventureState.phase === result`, `success === true`, and the selected team matches the challenge team. Change adventure phase to `won` in the same transaction as the award; undo must restore the ability to correct without awarding twice. Use shared arm/close for second-team 抢答, with the first team excluded. Decide how “公布答案” should appear for each adventure variant: reveal only after completion/failure so charades words or Yes/No prompts never leak during an active attempt. Use a shared finish action that first validates or safely aborts an unfinished adventure; keep early end available and labeled clearly in the question panel.
5. **Fix music timing and action dispatch.** Save playback position relative to clip start, clamp to `end-start`, reset to zero on replay, and make host/TV client calculations use the same duration. Host start/stop should call the common host wrapper. Finish or cancel stops audio and persists the stopped state. Preserve media authorization and Apple attribution.
6. **Align every cell with one host decision path.** Text/music/geography use the same two-attempt cap, oral answer, wrong/award/reveal/finish controls. Adventure uses its own pass criteria to enable shared scoring but uses the same final award receipt, undo and finish section. One active award per cell; corrections may target a completed awarded cell. No new question-bank fields or public answers are needed.
7. **Update copy and documentation.** Use the three stable headings and consistent button order. Remove old category-specific scoring instructions from `docs/games/trivia.md`, update `docs/system.md`, `spec.md` and `docs/plan.md` where behavior changed, and leave the ignored event bank private. Keep legacy numbered trivia copy distinct only for its amount/next-question controls.

## Verification matrix

- Server tests: each kind can select, arm/choose team, mark wrong or fail, open at most one second-team attempt, award the intended team once, reveal, finish, undo, re-award, and reject stale/duplicate commands. Test 1, 2, and 4-team rooms; after two failures the third team cannot buzz. Verify no balance changes for wrong or no-score finish.
- Adventure tests: first team chosen only by host; rules before timer; per-variant time/target checks; second team gets the same full condition; Yes/No prompt hidden until host shows it; consent replacement consumes a new prompt; photo score threshold and early finish; no word repeats in the night. Check that shared scoring cannot bypass a failed challenge.
- Music tests: local synthetic clip with nonzero start, stop/resume/replay, timeout, reconnect/restart, stale media request, award while playing, reveal and finish. The host can start TV playback without enabling host-device audio; TV still asks for its own sound gesture.
- Privacy/API tests: host answer and notes never enter TV/player snapshots before reveal; geography scene has no true coordinates in the public projection; no geocoding or answer-submission route exists; only host actions can score or reveal. Corrections and accounting remain private.
- Browser checks: in fresh disposable demo and event rooms, inspect host, TV and player at selection, armed, locked, wrong, second attempt, awarded, revealed and finished states for text, music, geography, all five adventure variants, and legacy numbered flow. Check keyboard focus/disabled state and narrow display layout. Rehearse with a configured Maps browser origin and with TV sound enabled. Run `npm run format:check`, `npm run typecheck`, `npm test`, `npm run build`, `npm run trivia:check`, and `git diff --check`; record exact results in `docs/plan.md`.

The refactor is complete only when the shared host sections render for every selected board cell and the server capability/transition tests match the displayed enabled controls. A physical projector and audio rehearsal is still a separate final event check.
